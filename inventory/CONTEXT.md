# Inventory(在庫)

商品を作るためのキットの在庫管理。入庫・出庫・スタッフによる予約と、注文によるキットの消費を扱う。基本は Django 標準の CRUD 構成だが、在庫数を動かす操作は `services.py` に集約し、在庫ログ・在庫切れの反映を必ず一緒に行う。既存の調理工程(Kitchen)には関わらない。

## Language

**キット (Kit)**:
商品 1 個を作るための材料一式。商品とは 1 対 1 で、商品 1 個につきキット 1 個を使う。キットを登録していない商品は在庫管理の対象外で、いくつでも注文できる。
_Avoid_: 材料、食材、在庫品

**実在庫 (On Hand)**:
店にある キットの数。入庫で増え、出庫・注文・予約の使用で減る。

**予約 (Reservation)**:
スタッフが団体注文やイベント用に手で押さえておくキット。予約の状態は「確保中」「使用済」「取消」の 3 つ。確保中の予約は注文に使えない。「使用」で確保した数をすべて実在庫から引き(一部だけの使用はしない)、「取消」で解放する。期限はない。
_Avoid_: 取り置き、引当(注文による消費と区別する)

**注文可能数 (Available)**:
実在庫 − 確保中の予約数。注文・出庫・予約の確保はどれも注文可能数までしかできない。常に「実在庫 ≥ 確保中の予約数」が成り立つ。

**在庫切れ (Out of Stock)**:
管理中のキットの注文可能数が 0 の状態。在庫切れになると Menu の商品に在庫切れフラグが立ち、注文画面に出なくなる。注文可能数が 1 以上に戻ればフラグは外れる。Menu の「品切れ」(スタッフが手で止める)とは別物。

**入庫 / 出庫 (Receipt / Issue)**:
専用画面または API からスタッフが実在庫を増やす / 減らす操作。出庫(廃棄・棚卸差異など)には理由が必須。キット登録時の初期在庫も入庫として記録する。

**在庫ログ (Stock Movement)**:
実在庫が動いた記録。種類は「入庫」「出庫」「注文で消費」「キャンセルで戻し」「予約を使用」。実在庫の変化 = 在庫ログの増減量の合計、が常に成り立つ。予約の確保・取消は実在庫を動かさないので記録しない。

**管理停止 (Inactive)**:
キットの在庫管理をやめた状態。在庫チェックの対象外になり(キット無しと同じ扱い)、在庫切れフラグも外れる。確保中の予約があると停止できない。在庫ログを残すため、キットは削除せず管理停止にする。再開もできる。

## Relationships

- **Ordering → Inventory(照会)**: 注文受付のトランザクションの中で `inventory.public.allocate_for_order` を呼び、キットを消費する。足りなければ `InsufficientStock` が返り、Ordering は自分の `OutOfStock` に詰め替えて注文を取り消す
- **Ordering → Inventory(イベント)**: `OrderCancelled` で、その注文で消費したキットを戻す(在庫ログをもとに戻すので冪等)
- **Inventory → Menu(照会・更新)**: キット登録時に `get_menu_item` で商品の存在を確かめ、注文可能数が動くたびに `set_out_of_stock` で在庫切れフラグを切り替える
